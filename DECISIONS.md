# DECISIONS

## Phase 1
1. **Repo repurposed in place.** Existing SDXL/RunPod Python files (handler.py, Dockerfile, README, etc.) left untouched; not deleted without being asked. Next.js app added at repo root. Removed `lib/` and `lib64/` from `.gitignore` (Python patterns that would have ignored `/lib/dsp`).
2. **Stack versions** pinned to latest at build time (Next 16.4.2, React 19.3.1, TS 7.0.2, Tailwind 4.3.3, Vitest 5.0.5). Zustand/IndexedDB/RNNoise not added yet (not needed in Phase 1). `noUncheckedIndexedAccess` left off (hot typed-array loops); `strict` is on.
3. **Input type is planar `Pcm`**, not `AudioBuffer`, so the same code runs in a Worker, Node and tests. `pcmFromAudioBuffer` adapts. Worker client copies buffers before transfer so callers keep theirs.
4. **Failure contract:** each measurement throws `MeasurementError(code)`. `measureAll` catches per measurement and returns `{ok:false,error}`, never a zero, and one failure doesn't hide the rest. Mono correlation throws `NOT_STEREO`. Digital silence throws. Values that are exactly 0 linear are clamped to -200 dB (`DB_FLOOR`) when converted to dB.
5. **Loudness** is one file (integrated/short-term/LRA share the K-weighting pass). BS.1770-4 K-weighting derived per sample rate; channel weights all 1.0; needs >= 3 s. Short-term timeline at 100 ms hop. LRA per Tech 3342 (-70 abs, -20 LU rel, P95-P10).
6. **True peak** uses a 12-tap/phase Kaiser(β=8) sinc 4x interpolator, NOT the exact BS.1770-4 Annex 2 coefficient table (not reproduced from memory). Validated with the fs/4@45° case (~0 dBTP); expect ±~0.1 dB vs a certified meter.
7. **Third-octave:** base-10 centres 25 Hz–16 kHz, Welch FFT 16384 pts Hann 50% overlap, power-averaged; low bands (25–40 Hz) have only 2–3 bins, so they are coarse.
8. **Two extra measurements** beyond the list, because the harness needs detectors for hum and plosives: `hum.ts` (low-percentile spectrum, harmonic prominence at 50/60 Hz ×4) and `plosive.ts` (20–80 Hz burst events). They are measurements first, detectors second (`detectors.ts`).
9. **Clipping** = runs of ≥4 samples pinned at the file's own per-polarity maximum (tolerance 1e-4), so normalised-after-clip files are caught. A pure-tone peak could false-fire; real vocals unlikely. True-peak overs are reported but not in the verdict.
10. **Hum detector** fires on ≥2 of 4 harmonics being prominent, so a lone tone (no harmonics) will not fire. Known gap; calibrate on real hum.
11. **Plosive detector** needs LF level, LF share of energy, and burst-over-median-LF together, so steady hum/rumble doesn't count. Low male F0 (~90–110 Hz) is the known risk on real audio; the harness includes a 95 Hz control and passes, but synthetic only.
12. **Noise print:** 2–5 s (spec said 2–3 s; allowance widened), must be stationary (block spread ≤10 dB) or it throws. SNR = power-subtracted speech over print RMS, speech = 100 ms blocks ≥10 dB above the print. DC removed before RMS.
13. **Harness set:** 4 generated vocals × (clean + 4 defects × mild/moderate/severe). Noise print for synthetic = first 2.5 s room tone of the (injected) file; for an uploaded file = quietest 2.5 s. Severity levels were picked around the placeholder thresholds, so perfect scores validate mechanics, not threshold realism.
14. **Dev route** 404s when `NODE_ENV=production` (verified). `agentRules: false` set so Next doesn't generate AGENTS.md.

## Phase 2
1. **Hybrid render, because of platform limits.** OfflineAudioContext exists only on the main thread (not in Workers), and Node has none. So: stages Web Audio expresses natively (HPF, EQ, saturation, reverb/delay) are each a single `OfflineAudioContext` render (never a live graph); stages that need sample-level control (RNNoise, expander, de-plosive, de-ess, compressor, limiter) are pure TS in a Worker and are unit-tested in Node. Consecutive same-kind stages are batched: native -> js -> native -> js -> native -> js (6 hops). Native stages are verified in real Chromium by `npm run e2e`, not by vitest.
2. **Chain order.** Phase 2's list omits noise-print; rule 5 includes it. Kept rule 5 literally: `clippingCheck -> noisePrint -> hpf -> noiseReduction -> expander -> deplosive -> deess -> eq -> compressor -> saturation -> space -> limiter`. `noisePrint` and `clippingCheck` are analysis-only (no audio change). The soft expander ("GATE") has no slot in rule 5, so it sits in the noise-reduction slot right after RNNoise.
3. **Internal format: 48 kHz mono.** RNNoise needs 48 kHz mono. Any source is resampled/downmixed once by an OfflineAudioContext (`prepareMono`); the source AudioBuffer is only read. The processed output is a new mono 48 kHz AudioBuffer (reverb adds a tail, so it can be longer). The "A" side of A/B is that same mono 48 kHz copy, so level matching compares like with like (a stereo file would otherwise read +3 dB).
4. **Config.** `lib/dsp/config.ts` is the only home for tuning numbers; `tests/config.test.ts` scans every stage file and fails on any numeric literal outside an allow-list of identities (0,1,2,3,4,10,20,1000,0.5, epsilons). Rationale strings also live in config. Web Audio quirks handled in code: Q for lowpass/highpass is in dB (config stores linear Q, converted in `native.ts`).
5. **RNNoise = real, not stubbed.** Jitsi's emscripten build (npm `@jitsi/rnnoise-wasm@0.2.1`), vendored: `public/wasm/rnnoise.wasm` (110 KiB) + 12 KB glue, loaded in the worker via `wasmBinary`. Details: `third_party/rnnoise/README.md`. Output delay (480 samples) is measured by an impulse test and compensated. The stage throws if the engine is missing; no JS fallback exists.
6. **De-esser = dynamic high shelf, zero-phase.** Sidechain is the 5-9 kHz band-pass peak envelope (as specified); the processed part is everything above `shelfHz` (4.5 kHz), obtained as x minus a forward-backward low-pass, so no phase cancellation error. A true narrow band split with 2nd-order filters only reached ~3 dB of a 10 dB setting; the shelf reaches ~5-7 dB at 7 kHz. Content below the shelf is untouched; when below threshold the output is bit-identical.
7. **Soft expander.** Quadratic soft knee, ratio 1.8, floor at `rangeDb` (-12 dB, so gain can never reach 0), 120 ms hold, 300 ms release, plus a 0.5 dB re-open deadband (found by the word-tail test: without it, envelope ripple on a 300 Hz tail re-opened the gate 450 times while decaying). Threshold = print noise floor + 8 dB; with no valid print it uses an absolute fallback and says so.
8. **De-plosive.** Detection never changes audio. Apply takes a `ConfirmedPlosives` value that only `confirmPlosives()` creates; the stage with no confirmation passes audio through and reports `awaiting-confirmation`; the store refuses to render while confirmation is pending; the UI shows each candidate with measured numbers and a Listen button. Apply is a time-varying low-shelf dip (<150 Hz, -12 dB) around confirmed events only (zero-phase LP subtracted).
9. **Clipped input made de-plosive false-fire (addendum 1), for real.** One-sided/asymmetric clipping creates slow DC-like LF shifts that look like pops: with the margin disabled, 54 clipped plosive-free files produced 31+ spurious events (F0 130-260 Hz). Fix: detection requires an onset rise (pops start abruptly); when clipping-check flags the file, the required rise is raised by `clippedExtraRiseDb` = 30 dB. Result: 0 spurious events on all 54 files; cost: on clipped files only ~78% of injected pops are still found (168/216). Margin 22 dB kept 192/216 but left 31 false events; 26 left 7. Chosen 30 because false positives were the stated concern; the confirm step covers misses. Calibrate on real clipped phone audio.
10. **Noise-print rejection** is five fail-closed layers (length, 100 ms energy spread, 10 ms bump, RNNoise VAD, periodicity with mains harmonics excluded). Hum prints are accepted. Full description in `lib/dsp/chain/noisePrint.ts` and the Phase 2 report. Validated only on synthetic speech and noise; real-speech behaviour is unverified (fixtures needed).
11. **Level matching** reuses Phase 1 loudness: integrated LUFS (>= 3 s), else active-block RMS (never mixed across methods). The louder side is attenuated; no gain is added. The waveform overlay is drawn at the matched levels.
12. **A/B playback** runs both pre-rendered buffers in lockstep and swaps gains with a 15 ms crossfade, so switching is sample-aligned and never restarts audio. Playback is not processing.
13. **Fixtures.** `fixtures/audio/` (git-ignored contents, README documents formats). Browser UI reads any decodable format via dev-only `/api/fixtures` routes; the Node suite reads 48 kHz WAV only (no resampler in Node) and says why when it skips. `next build` prints one filesystem-tracing warning for these dev-only routes; they 404 in production.
14. **Stack additions:** zustand (state), playwright-core (dev, e2e). Demo buttons on /repair import the dev-only defect generators only when `NODE_ENV !== "production"`.
15. **Phase 1 refactor:** `measure/plosive.ts` now exports `computeLfFrames` (shared with the de-plosive detector); `rng.ts` moved to `lib/dsp/rng.ts`. Phase 1 tests unchanged and green.

## Phase 3
1. **Everything is placeholder, loudly.** All four stock profiles (trap, boom-bap, drill, melodic-rap) carry `_placeholder: true`, a `_basis` naming the replacing corpus (N>=200 per genre), and an `_invented` statement: every number was invented by me; none is measured and none comes from an external source. The loader (`validateProfile`) throws on a profile missing `_placeholder`, a `_basis` with `N>=`, or any metric. `evaluate()` carries `profile.placeholder` and the UI shows a banner whenever it is true.
2. **Flag: corpus type.** Your example `_basis` said "full mixes". This app repairs isolated vocals, and a vocal stem's spectrum, loudness and crest are not comparable to a full mix's. So every `_basis` and every rule `calibration` names **isolated lead-vocal stems (acapella/stem releases)** measured with this repo's own pipeline instead. If you meant full mixes, the metrics need rethinking, not just the numbers.
3. **`threshold_pct` is a percentile**, not a percent deviation: the percentile (0-100) of the selected profile's corpus distribution for the rule's metric. Profiles store 7 percentile knots (5,10,25,50,75,90,95) per metric, interpolated linearly. `direction: above` fires when the user's value is strictly greater than that percentile's value, `below` when strictly less. This is why every threshold must name its corpus. The validator rejects a threshold outside the knot range.
4. **A delta is user minus the profile MEDIAN** (P50), in the metric's `delta_unit`: LU for LUFS/LRA, dB for levels and band shapes, `ratio` for clipped samples, `events/min` for plosives. Flag: the brief allowed "dB, ratio or LU"; a pop rate has no such unit, so `events/min` is the one addition. The reference's absolute numbers are not in the result type; a test walks every number in an evaluated result and checks none equals a profile value. The user's own measured values are shown (they are measurements, not the reference's).
5. **Band metrics are level-independent**: a band's power (or the power sum of several) minus the file's total level, so loudness doesn't change the spectral comparison. Phase 1's third-octave bands are on base-10 centres, so named bands match by nominal centre within 2% (250 -> 251 Hz etc.).
6. **Flag: "3.5 kHz" has no third-octave band.** Presence = power sum of the 3150 and 4000 Hz bands (2.8-4.5 kHz). Sibilance (5-9 kHz) = 5000+6300+8000 Hz bands (4.5-8.9 kHz). Boxiness = 250 Hz band. Stated in `lib/decision/metrics.json` definitions.
7. **Metrics are data too.** `lib/decision/metrics.json` registers each metric with the exact Phase 1 function (`measure_fn`), unit, delta unit, definition and a declarative `extract` spec (field / band_rel_db / ratio / per_minute). Units are cross-checked against the Phase 1 result's own unit; a mismatch makes the metric `unavailable`. `lib/reference/measureFns.ts` is the only bridge to Phase 1 and a test asserts each name is a real function. Nothing is re-implemented. New rules need no TypeScript (tested); a new metric of an existing kind needs none either.
8. **No reference => no coaching, in the type.** `evaluate(null, metrics)` returns `NoReferenceResult` = `{kind, reason, measurements}`: no `coaching`, `deltas`, `profile` or `notEvaluated` property exists. The reason text is a constant in `evaluate.ts`, carried in the result, and rendered by the UI from the result. Defect rules (clipping, plosive, noise) are also reference-gated, per rule 4: each has the profile's expectation as its baseline (clipping expectation 0).
9. **Unavailable is explicit.** A metric whose measurement failed (e.g. noise floor without a valid print) is `unavailable` with the reason; its rules are listed under "not checked", never silently skipped or zeroed.
10. **What is measured:** the original (48 kHz mono copy) by default, or the processed render via a selector. Measurement runs in the Phase 1 worker. The noise floor uses the chain's validated print region.
11. **No LLM, no network, no change to chain behavior.** Phase 2 e2e (31/31) and unit tests still pass.

## Phase 4
1. **Presets.** Five: `neutral` (the Phase 2 default, unchanged) plus `trap`, `boom-bap`, `drill`, `melodic-rap`. Each is an authored override over a deep clone of the default (`lib/presets/*.ts`); arrays (EQ bands) replace wholesale. `tests/presets.test.ts` walks every leaf of every resolved config: none undefined/null/non-finite, same type as the default's leaf, same key set. Presets are not allowed to change what analysis reads (clipping check, noise print, pop detection), the limiter, or the export/storage settings, so switching a preset keeps the analysis and the confirmed pops valid and just re-renders. The UI always shows "Active preset: X" and adds "(edited)" when the config has been changed since. All preset values are placeholders (`TODO: CALIBRATE`, real phone vocals, N>=50 per genre).
2. **Export order of operations (load-bearing).** `masterForExport`: measure integrated LUFS of the processed buffer -> apply gain -> RE-RUN the limiter at the ceiling -> re-measure. The limiter runs last even if the user bypassed the limiter stage. Target (-14), tolerance (0.5 LU), ceiling (-1 dBTP, from the limiter stage), iteration count, and caps are all in `config.ts`.
3. **How -14 LUFS and -1 dBTP interact.** Without limiting, a file can reach the target only if its peak-to-loudness ratio (true peak minus integrated LUFS) is at most ceiling minus target = 13 dB. A more dynamic file needs the limiter to pull peaks down, which also lowers loudness, so one gain step lands short; we iterate with a secant step on the measured result. Two things always win over the loudness target: (a) the true-peak ceiling (never exceeded), (b) a cap on how hard the limiter may work (`maxLimiterReductionDb`, 6 dB: beyond that we judge the result over-limited). When the target needs more than that, we deliver the loudest candidate that respects both, report status `ceiling-limited` and say by how many LU it is short. Silence throws; clips under 3 s (integrated LUFS undefined) get the limiter only and are reported `too-short-to-measure`. Evidence: a synthetic vowel stream after the drill chain has about 16 dB peak-to-loudness, so it exports at -14.9 LUFS, `ceiling-limited`, -1.00 dBTP; the neutral chain's version reaches -14.49 LUFS (`met`, 5 iterations).
4. **MP3 ceiling margin.** MP3 decoders can overshoot the PCM peak, so MP3 exports use a limiter ceiling 0.5 dB lower (`mp3.ceilingMarginDb`). Measured on the e2e file (decoded by Chromium, measured with Phase 1): decoded true peak -1.75 dBTP, i.e. no overshoot for this signal; 0.5 dB is kept as a conservative default (it costs 0.5 dB of loudness) until real material is tested.
5. **Export format.** 48 kHz **mono** (the chain is mono; stated in the export panel; never upsampled to fake stereo). WAV 16-bit with seeded TPDF dither (or 32-bit float via config); MP3 192 kbps CBR mono. No ID3/RIFF metadata is written: artist/track are used only in the filename.
6. **Filename** `{artist}_{track}_{preset}.{ext}` from the metadata form only. Sanitization (also in `lib/export/filename.ts`): NFC; whitespace runs and "_" -> "-"; control and zero-width/bidi characters removed; `\ / : * ? " < > | % # &` -> "-"; collapse "-"; trim "-", ".", spaces; cap each field at 60 code points (never splitting a surrogate pair); empty -> `artist`/`track`; whole name capped at 200 UTF-8 bytes. Case preserved. Windows reserved device names cannot occur (the name always contains "_" and an extension).
7. **MP3 encoder: lamejs 1.2.1, LGPL-3.0** (npm SPDX; source headers say LGPL v2-or-later). Shipped unmodified as its own file, loaded by a plain-JS worker, with licence texts, a `/licenses` page and a written obligations list: `third_party/lamejs/README.md`. Not legal advice; open items (whether serving JS is "conveying" for you, what of your own app source you must publish) are listed there. WAV-only is the documented fallback if that is unacceptable. The package's own LICENSE file is a LAME FAQ paragraph, not a licence text, so the LGPL/GPL texts were added from SPDX license-list-data.
8. **Two-step export (Prepare, then Save).** iOS Safari only allows `navigator.share()` inside a user gesture, and the render outlives that gesture window, so saving is a second tap. Delivery: Web Share API with the file where `canShare` allows it on iOS (share sheet -> Save to Files); otherwise `<a download>`; last resort `window.open(blobUrl)`. The UI shows which will be used.
9. **Persistence (IndexedDB, `lib/storage/idb.ts`, no dependency).** Stores: sessions, audio, renders, settings. An AudioBuffer is not structured-cloneable (Chromium: `structuredClone(audioBuffer)` throws `DataCloneError`, checked in the e2e), so we store `{sampleRate, channels: Float32Array[]}`. The saved source is the chain's own input (48 kHz mono float32, about 34.6 MB per 3 minutes), not the original file, so a reopened session feeds the chain exactly the same samples (proven: restored-session export is byte-identical to the original export). Saved: source PCM, the FULL resolved config (including user edits), bypass map, noise-print start, pop decision + confirmed ids, artist/track, export format. Kept: 5 sessions (`storage.maxSessions`), oldest evicted with its audio. Storage persistence is requested; usage is shown. Not saved: the original file's bytes, the processed output, intermediate render state. Saving session+audio is one transaction (a test caught a bug where a failed validation still committed the session; fixed by validating before opening the transaction).
10. **"Resume" is restart-from-saved-state, not mid-render resume.** A render is a chain of OfflineAudioContext passes and worker calls; an OfflineAudioContext render cannot be paused, serialized or resumed, and checkpointing every segment's output (6 hops, ~35 MB each) was not built. What is saved: source PCM + full config + decisions. What re-runs on reopen: the entire render. A "running" render record is written when a render starts and closed when it ends; if the page dies mid-render the record stays "running", and the next launch offers "Restore and re-render" (or Dismiss). Acceptable because renders take seconds on a desktop (not measured on a phone); the cost is redoing the whole render.
11. **PWA.** `manifest.json` (standalone, 192/512 + maskable icons generated by `scripts/make-icons.mjs`), `public/sw.js` (static, committed), `public/precache-manifest.js` (generated after `next build` by `scripts/build-precache.mjs`, gitignored; imported by the worker so a new build changes the worker bytes and triggers an update). Precached (46 files): `/`, `/repair`, `/licenses`, every `/_next/static` file (all JS/CSS/worker chunks), `rnnoise.wasm`, the MP3 worker + lamejs, icons, licence texts. Precached assets are cache-first; page navigations are network-first (4 s) with the cached page as fallback. New workers wait until tabs close, or the user taps "Update ready: reload". The service worker is registered only in production builds.
12. **Production builds use webpack, not Turbopack (found by testing).** With Turbopack, bundled workers are started as `turbopack-worker-*.js#params=...`; when a service worker answers that request from cache, Chromium loses the URL fragment and the worker throws "Missing worker bootstrap config", so the denoiser worker would die. `npm run build` therefore runs `next build --webpack`. Dev still uses Turbopack (no service worker in dev). Deployment hosts must run the same build command (the precache script runs after `next build`); a host that only runs `next build` would ship no precache manifest. Not tested on any hosting platform; `next start` was.
13. **iOS Safari limitations (platform behaviour I know of; NOT tested: no iOS device or simulator here).** (a) No `beforeinstallprompt`: install is Share -> Add to Home Screen; the app shows instructions on iOS. (b) Downloads: `<a download>` with blob URLs is unreliable in Home Screen (standalone) mode, hence the Web Share file path (iOS 15+); user-gesture requirement drives the two-step export. (c) Storage: Safari's tracking-prevention deletes script-writable storage (IndexedDB, Cache Storage, service worker registration) after 7 days without use in a Safari tab; Home Screen apps are exempt from that counter, but iOS can still evict under pressure and `navigator.storage.persist()` may not be honoured. (d) Background suspension: iOS suspends a backgrounded or locked page including workers and audio rendering, so a render can stall or be killed; there is no Background Sync. The interrupted-render recovery (restart from saved state) is the mitigation, not a fix. (e) Audio: an AudioContext starts suspended until a tap (we resume on Play); the requested sample rate may be ignored (playback resamples); iOS limits the number of concurrent AudioContexts (we close short-lived ones); Web Audio output has historically been muted by the hardware silent switch. (f) Memory: Safari tabs have a hard memory limit; the chain keeps several 35 MB-per-3-minute buffers, so long files may crash on older iPhones (untested). (g) We do not use Notifications. I do not claim parity with Android/desktop Chrome.
14. **Android Chrome install evidence is indirect.** In headless desktop Chromium with a persistent profile: Chrome's installability check (`Page.getInstallabilityErrors`) returns no errors, the manifest parses with no errors, and `beforeinstallprompt` fired. Not tested on a physical Android device. The default Playwright context is incognito-like and Chrome reports `in-incognito`, so the e2e uses a persistent profile.
15. **Lighthouse was not run.** Lighthouse 12 removed its PWA category (installability moved to DevTools), so it cannot produce a PWA report. The equivalent evidence is `npm run e2e:pwa`: installability via CDP, manifest checks, service worker active, every asset the `/repair` HTML references is in the cache, offline reload, offline full repair (RNNoise runs), offline WAV and MP3 export.
16. **Tests and audio.** All audio in unit tests and e2e is generated (tones, noise, the synthetic vocal, a generated stereo 44.1 kHz WAV): no real recordings exist in the repo. Exports are measured independently with the Phase 1 functions (`scripts/measure-wav.ts`).

## Phase 5
1. **Architecture as specified.** Tier 1 `evaluate()` -> `buildPhrasingPayload` (`lib/pro/findings.ts`) = `{ detected_findings[], metric_deltas{}, reference_genre, coaching_ids[] }` (+ `schema_version`, label, `reference_is_placeholder`) -> `/api/phrasing` -> LLM -> items constrained to the `coaching_ids` that were sent. The model cannot originate a finding: findings come only from the rules. No reference => no payload (`no-reference`), so no call is possible. Profile absolute values and percentiles are never sent, only rounded deltas.
2. **Model: `claude-haiku-5-5`, `effort: "low"`, structured output (`output_config.format`), SDK retries off.** Rewording ~3 short items from supplied text is the cheapest/fastest tier's job; all correctness is enforced by our validator, not by model capability. Swappable in `lib/pro/config.ts` (`PRO_CONFIG.model`).
3. **Flag: the SDK's schema helper does NOT enforce our enum.** `zodOutputFormat` demotes `enum`/`minLength`/`maxLength`/`maxItems` to the description string, so the API will not reject a bad `coaching_id`. Our strict zod parse + exact id-set check (`validate.ts`) is the real gate. Not a bug; do not rely on the API for it.
4. **Validation (`lib/pro/validate.ts`).** Every numeric token in the output must appear in the input (NFKC-normalised; foreign-script digits rejected; unit-aware so "3 dB" fails if only "3 LU" is in the input; spelled-out numbers rejected unless the input has them; identifier keys not scanned; ranges share the following unit). Also: exact id set (no extra, none missing, once each), topic guard (an item may not discuss another finding's topic, from `topics.json`), URLs rejected, strict shape and length caps. Retry max 2 (3 attempts), each retry tells the model what was rejected without supplying numbers; then Tier 1 raw text, HTTP 200, `source: "tier1-fallback"`.
3b. **Never fails closed.** Model error/timeout/unconfigured key/any thrown exception in the pipeline -> 200 + Tier 1 text. Only caller errors are non-200: 401/503 (auth), 400 (bad request), 413, 405, 429.
5. **Cache.** Key = SHA-256 of canonical JSON (sorted keys) of `{prompt_version, payload}`. Client: IndexedDB `responseCache` (DB v2, durable, re-validated on read so a poisoned entry is ignored). Server: in-memory TTL-LRU per edge isolate (best-effort, 24 h). Identical input => zero model calls. Fallbacks are never cached. Cache hits do not consume rate limit.
6. **Rate limit.** Per install (random 48-hex nonce kept in IndexedDB, sent as `x-install-nonce`): 20/h; per IP (`x-forwarded-for`): 60/h; only costly (non-cache) requests count. **Limitation:** in-memory per isolate, so it is best-effort, not a hard cap across a global edge fleet; a nonce is client-generated, so it limits honest clients and accidents, the IP limit and the Pro key are the real abuse controls. A durable shared limiter (KV/Redis) is the upgrade path.
7. **Pro gate = hand-issued key, hashed.** No billing exists. `PRO_TOKEN_HASHES` (comma-separated SHA-256 hex) in env; client sends `Authorization: Bearer <key>`. No hashes configured => 503, never open. This is a placeholder for real billing, not an entitlement system.
8. **Free never reaches Pro (three layers).** (a) `scripts/check-pro-boundary.mjs` (runs as `prebuild` and `check:boundary`): no Free file may import `lib/pro`, `components/pro`, the route, the `@pro` slot, `@anthropic-ai/sdk` or `zod`, or contain the string `/api/phrasing`; (b) the Pro UI lives in the parallel-route slot `app/repair/@pro`, so the Free layout/page import nothing from Pro; (c) `tests/pro/freePath.test.ts` asserts zero `fetch`/XHR/WebSocket/beacon calls on the Free pipeline and exercises the checker against bad fixtures. With no Pro key the Pro client also makes zero requests (tested). The Pro panel needs a user click ("Reword with AI"); nothing is sent automatically.
9. **Bug found by regression e2e and fixed.** Profile id `boom-bap` failed the id regex and the schema parse threw inside React render (page crash). Fixed: genre id allows `-`; `buildPhrasingPayload` returns `ok:false` (`invalid-payload`) instead of throwing; `metric_deltas` is built from the capped finding list; new test builds a payload for every shipped profile.
10. **Precache.** The edge route's server chunk had been listed in the precache manifest (Free users would download Pro server code). `build-precache.mjs` now skips `chunks/app/api/`; the checker ignores the generated manifest.
11. **Edge runtime.** Used as specified (`export const runtime = "edge"`). Next 16.4 prints "Edge Runtime is deprecated, use nodejs"; it still builds and runs. `lib/pro` is edge-safe (Web Crypto, fetch SDK, no `node:`), tested, so moving to `nodejs` is a one-line change if Vercel/Next drops edge.
12. **Cost per call (ESTIMATE, not measured: no API key in this environment).** Real prompt + JSON schema + 3-finding payload = 4,082 chars, about 1,280 input tokens at 3.2 chars/token; output about 370 tokens. At the rates in `PRO_CONFIG.costEstimate` ($0.10 in / $0.50 out per MTok, **my assumption for haiku-5-5; verify against current pricing and edit the config**): about **$0.0003 per call**, about **$0.001 worst case** (3 attempts). Cache hits cost $0. At 20 calls/install/hour cap that is at most about $0.006/install/hour.
13. **Tests are SYNTHETIC / FAKE-MODEL.** The model is a scripted fake (unit) or a stub HTTP server speaking the Anthropic wire format (e2e). No real model output was ever validated here; real-model behaviour (how often it needs retries) is unmeasured.
